# تصميم شاشات الإدارة

طُبّق تصميم بطاقة الأصناف المرجعي على 85 شاشة ونافذة خارج POS: المخزون، المشتريات، المبيعات والعملاء، الحسابات، التقارير، الموظفون، التأمين، الوصفات، الفروع، المستخدمون والإعدادات.

الثيم المشترك في `src/PharmacyERP.WPF/Themes/WorkspaceTheme.xaml`:

- الخلفية `#F9FAFB`، وبطاقات بيضاء بحدود خفيفة وحواف 8.
- الأزرار الرئيسية خضراء `#1F6F50`، والثانوية رمادية، والحذف أحمر فاتح.
- رؤوس الجداول داكنة `#1F2937`، وصفوف متناوبة مع تمييز أخضر للتحديد.
- خط Cairo المضمّن في التطبيق؛ لا يحتاج تثبيتاً في Windows.
- شريط إجراءات ظاهر في نماذج الإدخال وتمرير المحتوى الطويل، والتفاف أشرطة الأزرار.

كل شاشة تدمج الثيم داخل مواردها. لا تضفه إلى `App.xaml` أو نافذة POS؛ بذلك يبقى تصميم POS مستقلاً. تبقى معاينة ملصق الباركود باتجاه `LeftToRight`.

احتُفظ بالبحث المباشر وتحميل المزيد في بطاقة الأصناف، وبالأوامر والصلاحيات والتحقق من الإدخال والأعمدة في جميع الشاشات. هذه تعديلات عرض ولا تحتاج ترحيل قاعدة البيانات.

## التحقق

```bash
python3 tools/check-ui-contracts.py
dotnet build src/PharmacyERP.WPF/PharmacyERP.WPF.csproj -p:EnableWindowsTargeting=true
```

يقارن التدقيق عقود الواجهات بالمرجع `68ff9f1`، ويتأكد من عزل الثيم وتطابق ملفات POS مع المرجع. لا يحل هذا الفحص محل تشغيل الواجهات على Windows.

على Windows، راجع بطاقات الأصناف، إضافة صنف، استلام دفعة، خطوات المشتريات، لوحة التحكم، إعدادات الوصل ومعاينة الملصق. جرّب نافذة بحجم 1024×768 و1366×768، وكذلك تحجيم Windows عند 125%، وتحقق من ظهور إجراءات الحفظ وتمرير النماذج. افتح POS للتأكد من بقاء تصميمه مستقلاً.

## جلب التحديث

إذا كانت لديك نسخة التصميم المعدّلة محلياً من `ItemsView.xaml`، احفظها قبل السحب:

```powershell
git stash push -m "Backup custom ItemsView design" -- src/PharmacyERP.WPF/Views/Inventory/ItemsView.xaml
git pull --ff-only origin main
```

التصميم المرجعي أصبح مدمجاً في النسخة الجديدة، لذلك لا تطبّق النسخة المحفوظة فوقها تلقائياً. أوقف التشغيل القديم، ثم نفّذ Rebuild Solution وشغّل F5.
